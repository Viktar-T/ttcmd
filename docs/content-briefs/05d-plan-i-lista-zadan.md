## Reader position

Has read 0a–4e, 5a–5c. Has a repository whose whole history is two files and no
code, and a specification with five to nine criteria that a classmate has
reviewed. Has done this once, on the notatnik: a plan from a fresh session with
two files attached, six to eight tasks, one commit each. Has never ordered tasks
where the order mattered — the notatnik's order was obvious because the program
already existed.

## Carrying question

Ile zadań ma twoja aplikacja, w jakiej kolejności — i po czym poznasz, że
któreś jest za duże, zanim je zaczniesz?

## Anchor

**`specs/001-…/plan.md` and `tasks.md` in the student's own repository**, written
in the lesson and committed. The task list ends the lesson with a first task that
every one of the applications can have, phrased so that it names no feature: a
skeleton that starts and stops.

## Shape

Procedure with a narrative frame. Two hours; the deliverable is two committed
files.

## Owns · recalls · avoids

- **Owns** (proposed appendix rows): „zadanie to jedno posiedzenie”; the three
  shapes of a check; „najpierw zadanie najbardziej niepewne”.
- **Recalls**: 4c's plan and task list and „gotowe, gdy”; 4e's fresh session with
  exactly two files and „odpowiedź w rozmowie umiera z rozmową”; 5b's appetite,
  one clause with a link — the order rule is the same idea applied inside the
  week.
- **Avoids**: INVEST and SMART as acronyms (research-06 has them; the course's
  rule is stricter and simpler, and two acronyms would cost this short lesson its
  budget); Plan Mode and Implementation Plan as products (4d owns them); any
  application code.

## Exercises

1. Recall — the three shapes of a check, and the one-sitting test.
2. Action on the anchor — take the task you are least sure of and write its
   „gotowe, gdy” as a command or a file, then move it to the top of the list.
3. Build step — `plan.md` and `tasks.md` committed and pushed; the first task
   starts the next lesson.
4. Peer — swap task lists with a classmate and mark, without discussing the
   application, every task whose check you could not run yourself.

## Decisions

- **No task count is given as a rule** — rejected: „sześć do ośmiu, jak w
  notatniku”. The lesson gives the test (one sitting) and says what a count far
  outside the notatnik's range means, which is a question rather than a limit.
- **The first task is described, not written out** — rejected: a ready-made
  `T01` line. A ready-made first task would name a template and therefore a
  stack, and the module's rule forbids a lesson that presumes the shape of
  anyone's application.
- **The order rule is „riskiest first”** — rejected: „easiest first, to get
  moving”. Momentum bought on the easy half is paid for on Friday.
