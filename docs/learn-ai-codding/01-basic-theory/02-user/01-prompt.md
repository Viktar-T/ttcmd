When you work with an LLM, everything starts with a prompt.

A **prompt** is any message you send to a model or an AI service. It can be a question, a request, a command, or even a whole dialogue. It is how we “talk” to AI.

*Image on the platform: `image.png` — paste it here if you want the screenshot in the local notes.*

Example:

> Write me a one-paragraph summary of the plot of The Lord of the Rings.

That is a prompt. That is all. Nothing magical — just input text.

## Prompt engineering

**Prompt engineering** is the art of writing better prompts to get better results.

How you compose prompts matters. Prompt engineering includes structuring the request, using examples, and testing different styles — so the model gives the best answer.

Well-written prompts can turn a vague reply into something precise, creative, or ready for production. That is why prompt engineers — people who have this skill — became valuable in the AI world.

Recently, prompt engineering has been turning into **context engineering**. We will go into what context engineering actually is in the next chapter.

A basic rule for writing prompts has four parts:

- **Role** — who the model should “be” (for example, “You are an experienced developer”)
- **Task** — what the model should do (for example, “Summarize this API documentation”)
- **Format** — what the answer should look like (for example, “Give a bullet list”)
- **Constraints** — limits such as tone, length, or style (for example, “Keep it to 200 words”)

The more relevant and specific your context, the better the answer.  
That is the golden rule of prompt engineering.
